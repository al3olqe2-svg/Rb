# Stage 4 — Excel & UX

## الأساس وحدود التغيير

الفرع `stage-4-excel-ux` يبدأ من رأس المرحلة الثالثة `47cf59eed9b82d95c6b5be86bd7efa6b2bc26218`. PR #3 ما زال مفتوحًا ويستهدف المرحلة الثانية؛ لذلك يستهدف PR هذه المرحلة `stage-3-inventory`. لا دمج تلقائي للطلبات السابقة. بعد دمج الاعتمادات يمكن إعادة استهداف main.

الإصدار `0.4.0` وversionCode=4، مع بقاء `com.rb.app` و`rb.db` وRoom schema v1 وUUID والأرقام كما هي. التغيير في DAO استعلاما قراءة فقط. لا migration ولا destructive migration ولا صلاحيات تخزين أو إنترنت جديدة. لا تغيير في التحقق أو معاملات النقل والأرشفة والحذف أو تحليل الكاميرا. لا استيراد أو حسابات أو مزامنة أو سجل حركات، ولا إصدار نهائي Stage 5.

## الاستخدام والتصدير

من قائمة التطبيق أعلى المجموعات اختر **تصدير إلى Excel**، ثم **اختيار مكان الحفظ والتصدير**. يفتح `ACTION_CREATE_DOCUMENT` بنوع XLSX واسم `Rb_Inventory_YYYY-MM-DD.xlsx` حسب تاريخ الجهاز الفعلي. بعد إغلاق ونجاح الكتابة تظهر رسالة نجاح وخيارا الفتح والمشاركة بمنح قراءة للـ URI فقط. إذا لم يوجد قارئ Excel يبقى الملف محفوظًا ويمكن مشاركته أو فتحه من مدير الملفات.

- ورقة «المجموعات والشرائح»: كل المجموعات، حتى الفارغة، بعنوان الرقم والمسؤول وعدد الشرائح الفعلي، ثم آخر أربع خانات والرقم الكامل، وفي النهاية «الأرشيف العام».
- ورقة «جميع الشرائح»: صف لكل شريحة، الرقم الكامل وآخر أربع خانات ورقم المجموعة والمسؤول والحالة. الصف الأول ثابت وAutoFilter يتيح البحث والفرز.
- كلا الورقتين RTL، مع اتجاه LTR للخلايا الرقمية، وعناوين خضراء بارزة وأعمدة مخصصة والتفاف للنصوص الطويلة. كل الخلايا `inlineStr` بتنسيق نصي `numFmtId=49`، فلا تحويل عددي أو صيغة علمية، ولا تعبيرات `<f>`، حتى للأسماء التي تبدأ بـ `= + - @`. تُهرب رموز XML ومحارف التحكم وتسلسلات Excel الخاصة.
- تُقرأ المجموعات والشرائح في معاملة Room واحدة وقت بدء إنشاء التقرير، ثم يُكتب الملف خارج المعاملة وخيط الواجهة. هذا يمنع اختلاف الورقتين مع تغير المخزون أثناء الحفظ. يشمل المؤرشف ويستثني المحذوف نهائيًا.
- كتابة OOXML صغيرة ومتدفقة باستخدام `ZipOutputStream` وUTF-8 المدمجين في Android، دون إضافة مكتبات إنتاج ثقيلة أو تبعيات جديدة. تُنشأ حزمة ECMA-376 كاملة بعلاقاتها وأنواع المحتويات والأنماط، وليست CSV بامتداد مغير.
- يُنشأ الملف أولًا في cache خاص ثم يُنسخ إلى وجهة SAF، مع التحقق من أخطاء الكتابة والإغلاق. يُحذف الملف المؤقت في النجاح والفشل؛ تُجرَّب إزالة وثيقة الوجهة غير المكتملة عند الفشل. بعض المزودين قد لا يدعمون الحذف؛ تشرح الرسالة احتمال بقاء ملف ناقص.
- تُمنع إعادة بدء التصدير أثناء المنتقي أو الإنشاء؛ تبقى الحالة في ViewModel على مستوى التطبيق عند التنقل وتدوير الشاشة. الإلغاء من المنتقي لا يعرض خطأ. تظهر رسالة خاصة لـ ENOSPC/EDQUOT ورسالة قابلة للتصرف للأخطاء الأخرى. لا قياس مسبق مفترض للمساحة لدى مزود بعيد.
- حدود Excel: تُرفض البيانات التي تتجاوز 1,048,576 صفًا لأي ورقة أو 32,767 حرفًا لرقم في خلية قبل الكتابة، دون اختصار البيانات. هذه أكبر بكثير من حجم الاستخدام المستهدف. الملف تقرير وليس نسخة قابلة للاستيراد.

## الواجهة وتجربة الاستخدام

ثيم Material 3 موحد فاتح بألوان محايدة وأخضر محدود، وزوايا 6–20dp وخطوط ذات أحجام وارتفاع أسطر واضحة. ملخص إجمالي مضغوط وصفوف مجموعات أكثر كثافة، وفلتر برقم المجموعة أو المسؤول مع مسح سريع وحالة فارغة خاصة.

تمييز خلفية الصف المحدد بالإضافة إلى Checkbox ودلالة الوصولية، وأشرطة تحديد وفرز وإجراءات تتكيف مع العرض الضيق. أرقام كاملة أوضح مع بقاء آخر أربع خانات أبرز منها. الأرشيف يشرح أن الشرائح غير مخصصة وكيفية نقلها، والبحث يدعم زر البحث في لوحة المفاتيح وإغلاقها عند فتح التفاصيل أو الإجراءات. تستمر تفاصيل الشريحة في إتاحة النسخ دون تغيير الرقم.

في المسح: آخر قراءة كاملة مع آخر أربع خانات والعدد، وإشارة مرئية للتكرار ورسائل معلنة لقارئ الشاشة، وتمييز حالات النقل التي تحتاج موافقة، وأزرار دفعة متناسقة. تستخدم المراجعة خريطة مبنية مرة لكل خطة بدل البحث الخطي لكل صف. تبقى الموافقات ومنطق الكاميرا كما في المرحلة الثانية.

قوائم LazyColumn ومفاتيح السجلات الثابتة والتحديد بالمعرف باقية. البيانات محملة كقوائم في الذاكرة؛ لا paging أو تغيير لسلوك البحث الجزئي، وهو مناسب لحجم مئات/آلاف الشرائح دون ادعاء قياس على هاتف فعلي.

## التحقق

نجح محليًا بتاريخ 2026-11-14 على JDK 17 وSDK 36 الأمر `./gradlew testDebugUnitTest lintDebug assembleDebug`: **77 اختبارًا، صفر فشل أو خطأ أو تجاهل**، متضمنة اختبارات المراحل السابقة الـ61. Lint: صفر أخطاء، والتنبيهات الثلاثة السابقة فقط لترقيات Lifecycle/Navigation غير الملائمة لسلسلة البناء الحالية؛ لا تنبيهات جديدة. أُصلح تنبيه احتفاظ السياق باستخدام AndroidViewModel وتطبيق Application صراحة.

نجح فحص مستقل باستخدام Python `zipfile` وXML و`openpyxl 3.1.5` لتحميل عينة XLSX وإعادة حفظها وقراءتها: العلاقات صحيحة، القيم والأصفار مطابقة، جميع خلايا البيانات نصية بتنسيق `@`، الاسم الذي يبدأ بـ `=` بقي نصًا، RTL وAutoFilter وتثبيت الصف سليمة. لم يُفتح الملف في Microsoft Excel فعليًا.

راجعت لقطات Robolectric الأصلية للمجموعات والتحديد والأرشيف والمسح والتصدير بعرض 320dp، وقُصّر عنوان بحث المجموعات بعد المراجعة. نجح `apksigner verify` بتوقيع v2، وأكد `aapt` الإصدار 0.4.0 وversionCode=4 وminSdk=26 وtargetSdk=36 دون INTERNET أو صلاحيات تخزين. حجم Debug APK نحو 85 MiB. لم يُستخدم هاتف فعلي.

الاختبارات الجديدة تغطي بنية ZIP/XML وخصائص النص والـ RTL والتصفية، أرقامًا أطول من دقة Excel والأصفار وتطابق آخر أربع خانات، الأسماء العربية والشبيهة بالصيغ، escaping، المجموعات الفارغة والأرشيف، 3000 شريحة، رفض تجاوز حد الخلية، أخطاء الكتابة والتسمية، لقطة Room بعد النقل والأرشفة والحذف، وحفظ SAF عبر مزود `content://` اختباري على API 26 و35، وإلغاء المنتقي والفشل وإعادة المحاولة وعدم تعديل قاعدة البيانات. اختبارات Compose تشمل وصول التصدير والتحديد على شاشة 320dp وفلترة المجموعات. تُنتج لقطات في `app/build/reports/screenshots` وعينة مستقلة في `app/build/reports/export/inventory.xlsx`.

## APK والتوافق

يرفع GitHub Actions حزمة `Rb-stage4-debug` وتقارير التحقق، مع استمرار فروع تشغيل المراحل السابقة وإضافة قاعدة PR إلى `stage-3-inventory`. لا مفاتيح توقيع جديدة في Git ولا تغيير لآلية توقيع Debug.

التحديث فوق نسخة سابقة يتطلب شهادة توقيعها نفسها. مفتاح النسخة السابقة غير محفوظ في المستودع، وقد يختلف توقيع Debug المحلي أو Actions. رفع versionCode وحفظ المخطط لا يتجاوزان شرط Android هذا. لا تحذف التطبيق أو تمسح بياناته لحل اختلاف التوقيع؛ ابنِ باستخدام مفتاح النسخة المثبتة.

لا جهاز فعلي متصل، ولا ادعاء باختبار عتاد الكاميرا أو مزودي المستندات الخارجيين أو فتح الملف في Microsoft Excel الفعلي. اختبار الكاميرا الواقعي والإصدار النهائي يظلان خارج هذه المرحلة.
