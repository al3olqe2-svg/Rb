# Stage 6 — 0.6.0 (6)

## سجل النقل
الوصول من قائمة التطبيق ← «سجل النقل»، بترتيب الأحدث أولًا، ثم تفاصيل العملية مع جميع أرقام الشرائح، وآخر أربع خانات بارزة، ونسخ الرقم الكامل. القوائم LazyColumn مع حالات التحميل والخطأ والفراغ.

Room v2 يضيف `transfer_records` و`transfer_record_items`. المصدر والوجهة محفوظان بمعرفيهما ولقطات الرقم والمسؤول وقت التنفيذ، وأرقام الشرائح لقطات نصية مستقلة. لا علاقة FK بالمخزون أو المجموعات؛ حذف الشريحة أو المجموعة الفارغة وتغيير المسؤول لا يغيّر التاريخ. العدد مشتق من عناصر العملية.

`changeInventory` و`saveScan` يكتبان السجل في معاملة تحديث المخزون نفسها، بعد إعادة التحقق من الصفوف والوجهة. النقل الجماعي يسجل عملية لكل مصدر/وجهة. تكرار الخطة القديمة يُرفض بعد تنفيذها؛ حماية busy الحالية تمنع تكرار التأكيد. الصفوف الباقية في الوجهة لا تُنقل ولا تسجل. الإضافات والأرشفة والاستعادة والحذف وتغيير المسؤول لا تسجل. لا تاريخ قديم أو عمليات معلقة أو سجل تغييرات عام.

`MIGRATION_1_2` تنشئ الجداول والفهارس الجديدة فقط، ومسجلة في RbApplication عند فتح `rb.db`. كيانا groups وsims ومخططاهما مطابقان لـv1، ومعرفات البيانات والحزمة com.rb.app محفوظة. لا destructive migration ولا إنترنت أو مزامنة. تصدير Excel ما زال تقرير المخزون نفسه.

## GroupLabelScanner
زر الكاميرا في حقل رقم المجموعة يستعمل مسارًا مستقلًا داخل المحلل، دون تغيير استخراج SIM أو إجماعه الزمني. Barcode/OCR المحليان يرسلان النص وزوايا المضلع وزاوية السطر في فضاء الصورة المصحح بدوران CameraX.

- يرشح أرقام الملصق الطويلة 18–22 خانة فقط؛ الإدخال اليدوي للمجموعة يبقى 1–64 خانة. لا تحويل رقمي أو إصلاح خانات.
- يحوّل الإحداثيات إلى محوري قراءة النص اعتمادًا على زاوية OCR الموجهة، بما يشمل دوران 90/180/270 درجة. يرفض الترجيح الآلي عند غياب الاتجاه أو اختلافه بين السطور.
- يحتاج لترجيح الأعلى إلى باركودين بقيمتين مختلفتين، ومطابقة نصية كاملة لكل منهما بجواره، ومحاذاة وفصل مكاني واضحين، وترتيب متفق للنص والباركود. لا ترتيب حسابي للأرقام؛ عكس القيم مع ثبات المواقع يعكس النتيجة.
- GroupLabelCapture يستخدم نافذة سبعة إطارات؛ ثلاث قراءات للمرشح، وخمس للرقم المنفرد، وثلاث أدلة مكانية متفقة لترجيح الأعلى. فجوة 2500ms تمسح الأدلة القديمة. القراءات المتعارضة تبقى اختيارًا يدويًا.
- تثبت القائمة كاملة حتى التأكيد أو «إعادة المسح»، بما في ذلك عند اهتزاز اليد أو ورود إطارات أخرى. الأعلى الموثوق يظهر أولًا بعلامة واضحة؛ يظل التأكيد الصريح مطلوبًا. إذا غابت الأدلة أو ظهر رقم واحد فقط، يختار المستخدم بعد مراجعة الرقم الكامل.
- المرشحون والاختيار المثبت محفوظون عبر rememberSaveable عند إعادة إنشاء الشاشة. التأكيد محمي من النقر المتكرر، ويعيد الرقم كاملًا إلى النموذج القابل للتعديل قبل الحفظ. منع تكرار رقم المجموعة وإبراز آخر أربع خانات في قائمتها محفوظان.

## التحقق
التحقق المحلي على JDK 17 وSDK/Build Tools 36:
- نجح `./gradlew testDebugUnitTest lintDebug assembleDebug assembleDebugAndroidTest`.
- 114 اختبار JVM/Robolectric: صفر فشل أو تجاهل. يشمل Room على API 26 و35 واختبارات المراحل السابقة.
- Lint: صفر أخطاء، وثلاثة تنبيهات تحديث تبعيات موجودة سابقًا (Lifecycle/Navigation)، دون تغيير إصدارات الإنتاج.
- اجتاز Debug APK فحص apksigner وzipalign؛ الحزمة com.rb.app، الإصدار 0.6.0 (6)، minSdk 26، targetSdk 36، وصلاحية الكاميرا فقط دون INTERNET أو صلاحيات تخزين واسعة.
- تمت مراجعة لقطتي السجل والتفاصيل من اختبارات Compose بعرض 320dp؛ الاسم والرقم والوقت والنسخ واضحة، وصفوف المصدر والوجهة تلتف عند ضيق العرض.
- بُني APK اختبار Android محليًا؛ التنفيذ الفعلي لاختباري الصور على محاكي API 26 في Actions، ونتيجته المرجعية في Checks لطلب الدمج. لا محاكي محلي أو جهاز متصل في هذه البيئة.

الاختبارات الجديدة: نقل فردي وجماعي، جميع الأرقام بما فيها آخر أربع متطابقة، مصادر متعددة في دفعة مسح مع قبول ورفض النقل، استثناء الأرشيف والحذف والإضافات، أسماء تاريخية بعد التعديل وحذف البيانات، فشل كتابة عناصر التاريخ والتراجع عن نقل/إضافة وسجلات سابقة من مصدر آخر، خطط قديمة ومنع التكرار، وترحيل قاعدة v1 حقيقية من المخطط المحفوظ عبر مصنع قاعدة الإنتاج ثم إعادة فتحها.

اختبارات الملصق تستعمل أرقام المثال، الباركودين، دورانًا وميلًا وعكس القيم واختلاف/غياب النص والاتجاه، قراءة منفردة، مرشحين ملتبسين، انتهاء الأدلة وتثبيت النتائج. [العينة الاصطناعية](samples/group-label.svg) و[شرحها](samples/README.md) تمثلان شكل الملصق. اختبارات JVM تحقن ملاحظات هندسية عند حدود ML Kit. يضيف GroupLabelImageTest اختبار Android يستخدم Barcode وOCR الفعليين على نسخة PNG من العينة: الصورة المستقيمة تتطلب قراءة الرقمين وترجيح العلوي، والصور المدورة لا يجوز أن ترجح السفلي، والاقتصاص المنفرد يتطلب مراجعة يدوية. يُشغل هذا الفحص على محاكي Actions API 26؛ نجاحه لا يقيس جودة الكاميرا الميدانية.

اختبارات Compose تتحقق من الوصول من القائمة والتفاصيل واللقطات التاريخية والنسخ والرجوع والفراغ بعرض 320dp، وتنتج لقطات في `app/build/reports/screenshots/stage6`. تبقى اختبارات المراحل السابقة ضمن التشغيل الكامل، بما فيها Excel والسلاسل والمسح المتتابع.
